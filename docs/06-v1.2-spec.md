현재 저장소의 개발 진행 상태를 확인하고, 완료되지 않은 Phase부터 순차적으로 개발한다.

## 2. 서비스 목적

PM.zip은 단순 업무관리 도구가 아니라 PM의 업무 수행, 서비스 개선, 데이터 분석, 사업 성과 및 개인 기여도를 통합 관리하는 서비스다.

다음 5개 영역을 연결한다.

1. 프로젝트 및 요구사항 관리
2. 서비스 이용 성과
3. AI 품질 및 교육 효과
4. 사업 성과 분석(Business Impact)
5. PM 업무 성과 및 개인 KPI

프로젝트별로 서로 다른 데이터 소스, 지표, 목표, 분석 가설을 설정할 수 있어야 한다.

초기 적용 프로젝트는 Galaxy Coach로 한다. 특정 프로젝트에 종속되지 않는 공통 구조로 개발한다.

외부 서비스 인증 정보를 공통으로 관리하고 프로젝트별로 선택하여 재사용할 수 있도록 한다.

- Microsoft Teams

- Google Calendar

- GitHub
- 외부 데이터베이스

업무용 계정과 개인용 계정의 인증 및 데이터 접근 범위를 분리한다.

### 3.2 프로젝트 설정: 데이터 소스 관리

프로젝트별로 다음 항목을 설정할 수 있도록 한다.

- 연결 계정
- 데이터 소스
- 수집 대상
- 수집 조건 및 필터
- 동기화 주기
- 마지막 수집 일시
- 자동 수집 활성화 여부
- 연결 테스트
- 오류 및 재시도 이력
- 연결 해제

하나의 계정을 여러 프로젝트에 연결할 수 있고, 하나의 프로젝트에 동일 서비스의 여러 데이터 소스를 연결할 수 있어야 한다.

특정 프로젝트의 연결 해제가 다른 프로젝트에 영향을 주지 않도록 한다.

동일 원본 메시지나 문서는 중복 저장하지 않고 프로젝트별 관계를 관리한다. 원본에 대한 접근 권한이 다른 프로젝트로 확장되지 않도록 한다.

## 4. Galaxy Coach GA4 직접 연동

### 4.1 연동 정책

기존 CoachGlobalData 및 CoachData Apps Script의 데이터 조회·집계 로직을 참고한다.

Apps Script 및 Google Sheets를 PM.zip 운영 의존성에서 제외한다.

PM.zip 백엔드에서 GA4 Data API를 직접 호출한다.

- Property ID: 운영 설정에서 별도 지정 (공개 저장소에는 실제 식별자 미포함)
- Google Cloud 프로젝트: 운영 설정에서 별도 지정
- 권한 범위: analytics.readonly
- 인증 방식: 승인된 OAuth 2.0 또는 서비스 계정
- 인증 정보는 서버에서 암호화하여 관리
- 프론트엔드 및 저장소에 비밀정보 노출 금지

현재 Google Cloud 콘솔은 MFA 요구로 접근이 제한되어 있으며 GA 사용자 관리 권한도 확보되지 않았다.

실제 인증 연결 전에는 합성 데이터와 Mock API로 구현 및 테스트한다. 운영 연결에 성공한 것처럼 처리하지 않는다.

### 4.2 GA 이벤트 정의

Main UU / Main Count

- eventName = screen_view
- unifiedScreenName = GALAXY_COACH_SCREEN
- Metrics: totalUsers, eventCount

Start UU / Start Count

- eventName = GALAXY_COACH_SIMULATION
- Metrics: totalUsers, eventCount

Done UU / Done Count

- eventName = GALAXY_COACH_REPORT
- Metrics: totalUsers, eventCount

중요: 기존 galaxy_coach_simulation_Done 이벤트는 훈련 완료 지표 산정에서 제외한다.

Score

- eventName = GALAXY_COACH_REPORT
- Dimension: customEvent:nsp_value
- 허용 값: 1, 2, 3, 4, 5
- Metric: eventCount

Country

- Dimension: countryId

Sales Case

- Dimension: customEvent:nsp_category
- switcher
- upgrader
- retention

기존 코드에서는 Done Count를 S1~S5의 합계로 산출하는 경우가 있었다. 신규 기준에서는 전체 REPORT 이벤트 횟수와 유효 점수 이벤트 횟수를 각각 저장하여 차이를 검증할 수 있도록 한다.

### 4.3 산출 지표

- Main UU
- Main Count
- Start UU
- Start Count
- Done UU
- Done Count
- 진입 대비 시작률 = Start UU / Main UU
- UU 완료율 = Done UU / Start UU
- Count 완료율 = Done Count / Start Count
- 인당 평균 훈련 횟수 = Start Count / Start UU
- 인당 평균 완료 횟수 = Done Count / Done UU
- S1~S5 점수별 분포
- 평균 평가점수 = 점수별 건수 가중평균
- 고득점 비율 = (S4+S5) / 유효 점수 건수
- 저득점 비율 = (S1+S2) / 유효 점수 건수
- WAU
- MAU
- 국가별 이용 현황
- Sales Case별 이용 현황

추가 데이터 확보 시:

- S+ 활성 사용자 대비 Coach 이용률
- 신규 이용자 수
- 재이용률
- D7/D30 리텐션
- 평균 대화 턴 수
- 실제 세션 완료율
- 개인별 평가점수 개선폭

### 4.4 데이터 정합성 정책

- 일별 UU를 합산하여 주간·월간 UU를 산출하지 않는다.
- 국가별 또는 Sales Case별 UU를 단순 합산하여 전체 UU를 산출하지 않는다.
- 전체 UU는 해당 기간을 기준으로 GA에서 별도 조회한다.
- 분모가 0이면 N/A로 처리한다.
- 결측값과 실제 0을 구분한다.
- REPORT 이벤트의 중복 발생 여부를 검증한다.
- GA 이벤트 기반 완료율과 실제 세션 단위 완료율을 구분한다.
- 수집 시점, 조회 기간, 필터, 지표 정의 버전을 저장한다.
- 과거 데이터와 최신 데이터의 집계 기준 변경 이력을 관리한다.
- GA 보고서 제한, 데이터 누락 및 집계 품질 정보를 표시한다.

## 6. 사업 성과 분석 — Business Impact

프로젝트별 공통 기능으로 구현한다.

### 6.1 성과 가설 관리

사용자가 분석 가설을 등록할 수 있도록 한다.

예시:

- Galaxy Coach 이용률이 높은 국가의 판매 증가율이 더 높은가?
- 반복 훈련이 많은 국가에서 판매 실적이 개선되는가?
- Switcher 훈련 이용률과 타사 고객 전환율 사이에 관계가 있는가?
- Upgrader 훈련 이용률과 신제품 구매율 사이에 관계가 있는가?
- 특정 제품 관련 훈련 증가 이후 해당 제품의 판매 추이가 개선되는가?

가설별 독립변수, 종속변수, 분석 기간, 분석 단위, 시차, 비교 그룹, 통제변수, 데이터 출처를 설정한다.

### 6.2 사업 성과 데이터 소스

- 고객사 제공 판매 데이터
- 국가별 판매 증가율
- 전년 동기 대비 판매 성장률
- 전작 대비 판매 증가율
- 판매 목표 달성률
- 국가별·제품별 시장조사 데이터
- 삼성전자 공식 실적 자료
- Counterpoint Research 등 외부 시장조사 자료
- 사용자 등록 Excel/CSV

판매 데이터와 외부 시장조사 데이터는 아직 확보되지 않았다.

출처, 이용 권한, 조사 대상, 데이터 기간, 측정 단위 및 판매량/출하량 구분을 기록한다.

접근할 수 없는 유료 데이터는 임의 생성하거나 우회 수집하지 않는다.

### 6.3 분석 차원

- 글로벌
- 권역
- 국가
- 법인
- 제품
- Sales Case
- 일간

### 6.4 분석 기능

- 국가별 Coach 이용률과 판매 성장률 비교
- 이용률 상위·중위·하위 국가 그룹 비교
- 상위 5개국 / 하위 5개국 비교
- 산점도
- 추세선
- Pearson 및 Spearman 상관계수
- 분석 대상 표본 수 및 결측률
- 이상치 탐색
- 1~4주 시차 분석
- 배포 전후 분석
- 비교군 기반 분석
- 조건 충족 시 Difference-in-Differences 분석
- 국가별 출시 일정 및 프로모션 영향 기록
- 기존 판매 추세와 시장 상황 고려

이용률 산출 시 S+ 활성 이용자 등 적절한 분모를 사용한다. 해당 분모가 없으면 이용자 수를 이용률로 표시하지 않는다.

국가별 차이를 통제하지 않은 단순 비교와 인과관계 추정을 구분한다.

### 6.5 AI 성과 분석

AI가 다음 항목을 추천하거나 분석하도록 한다.

- 새로운 성과 분석 가설
- 유의미한 변화 후보
- 국가별 특이사항
- 급격한 지표 변화
- 성과 개선 가능성이 높은 영역
- 추가 확인이 필요한 데이터
- 분석 한계
- 향후 개선 방향
- 보고서 초안

통계 계산은 코드 기반으로 수행하고 AI가 수치를 임의 생성하지 않는다.

상관관계를 인과관계로 과장하지 않는다.

AI 분석 결과는 근거 데이터 및 출처와 연결하고 사용자 승인 후 확정한다.

## 11. 개발 및 테스트 지시

1. 기존 v1.1 명세 및 코드 검토
2. 현재 Phase 및 구현 상태 확인
3. 추가 요구사항에 고유 ID 부여
4. PRD/FRD/Architecture/Phase/Test 명세 업데이트
5. 기존 Phase 순서 및 완료 조건 유지
6. GA 연동 공통 인터페이스와 지표 정의 설계
7. 합성 데이터 기반 GA Connector 테스트
8. 프로젝트별 연동 및 데이터 권한 테스트
9. 성과지표 산출 엔진 검증
10. Business Impact 통계 분석 엔진 검증
11. 대시보드 및 보고서 구현
12. Teams 등 추가 연동 모듈 확장
13. 전체 회귀 테스트

추가 기능의 구현 Phase를 명시하고 기존 필수 Phase를 건너뛰지 않는다.

각 Phase 완료 시 다음을 보고한다.

- 구현 완료 기능
- 요구사항 ID
- 변경 파일
- 테스트 실행 결과
- 미완료 기능
- 발견된 오류 및 해결 내역
- 보안 검토 결과
- 다음 Phase 착수 조건

실행하지 않은 테스트는 통과 처리하지 않는다.

실제 회사 데이터 사용, 외부 서비스 연결, 운영 배포는 승인 전 수행하지 않는다.

기존 Apps Script 및 운영 시스템은 변경하지 않는다.

인증 정보가 부족하더라도 해당 부분만 차단 상태로 기록하고, 나머지 개발은 합성 데이터로 진행한다.

지금부터 기존 개발 상태와 명세를 확인하고 순차적으로 개발에 착수한다.

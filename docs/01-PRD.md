# PRD — PM.zip (Product Impact Tracker)
버전 1.1 / 2026-11-25 / 초안

## 1. 배경과 문제
제품의 월별 개선 내용이 다르고 요구사항 수집월, 개발월, 배포월, 결과 관측월이 불일치한다. 기획자가 필요한 지표와 로그를 배포 후에야 발견하면 기준값이 없고 성과를 검증할 수 없다. 요구사항 관리 도구는 납기와 완료 여부를 중심으로 하며 문제 해결 효과와 개인 기여도를 연결하기 어렵다.

## 2. 제품 목표
- 요구사항 입력 즉시 문제·대상·가설·KPI·필요 로그를 검토할 수 있게 한다.
- 월별 핵심 개선 목표가 바뀌어도 서비스 공통 지표와 기존 기능 지표를 유지한다.
- 배포 전 측정 준비 및 배포 후 결과 비교를 하나의 이력으로 연결한다.
- 성과의 근거와 한계를 보존하고 월별/기능별 보고서 및 향후 포트폴리오 재료를 만든다.

비목표: Jira/P4 대체, 범용 BI, 자동 인과관계 판정, 실시간 모든 외부 데이터 연동, 자동 고객사 보고 발송.

## 3. 사용자
주 사용자: 복수 프로젝트를 운영하는 서비스 기획자/PM. 협업 사용자(후속): 개발자, 분석가, QA, 관리자. MVP는 계정당 개인 워크스페이스; 팀 권한은 이후.

## 4. 핵심 흐름
프로젝트 생성 → 원문 여러 건 수집 → 과제 분리/중복 검토 → 월별 전략 연결 → 가설 및 측정 계획 추천/수정/승인 → 기준 데이터 및 로그 준비 → 배포 기록 → 관측값 등록 → 과제별 효과 검증 → 월별 리포트 및 후속 과제 생성.

## 5. 지표의 3계층
| 계층 | 예시 | 수명 |
|---|---|---|
| 서비스 고정 | WAU, MAU, 시작·완료율, D7/D30, 복귀율 | 장기, 버전 관리 |
| 월별 집중 | 해당 월 목표별 지표 선택 | 월별 우선순위 변경, 지표 자체는 재사용 |
| 과제별 | STT 실패율, 위젯 CTR, 평가 준수율 | 과제 연결, 배포 기준 관측 |

하나의 과제에 복수 지표, 지표 하나에 복수 과제 연결. 월별 전략은 수집월·목표월·배포월·관측월과 별개. 기존 지표는 필요 시 모니터링 종료 처리(삭제 아님). 월간 목표와 지표 목표값은 사용자 승인 전 미정.

## 6. MVP 범위 (P0)
프로젝트/인증, 요구사항 수집함, 과제 연결, 월별 전략, AI 또는 규칙 기반 측정 계획, 지표 사전, 준비 체크, 배포/외부 이벤트 이력, 수동/CSV 데이터 입력, 결정적 지표 계산, 전후 비교, 월별/과제별 리포트 및 Markdown 내보내기. AI 연결은 서버 환경변수로 선택하며 미설정 상태 명시.
P1: Excel, 사용자 단위 코호트, 자동 추출 요청서 템플릿 확대, 보고서 PDF, 알림, 장기 비교 대시보드.
P2: Gmail/Slack/P4/GA/DB 연동(권한 및 보안 승인 후), 팀 워크스페이스, 포트폴리오 내보내기, 자동 모니터링.

## 7. 제품 성공 기준 (목표 제안, 실측 아님)
- 합성 요구사항 3개를 등록하여 각기 다른 측정 계획과 다중 지표를 저장할 수 있음.
- 기준값 미확보 과제를 배포 준비 화면에서 확인 가능.
- 월을 넘기는 과제의 배포와 관측이 누락 없이 보고서에 반영됨.
- 동일 데이터/지표 버전으로 계산 재실행 시 동일 결과.
- 사용자 승인 없이 AI 초안 확정 또는 성과 수치 생성 불가.
- 실제 사용성 목표: 측정 계획 초안 작성 시간 및 배포 전 기준값 확보율을 파일럿에서 측정하고 이후 목표 설정.

## 8. 파일럿 시나리오
8월 1차 리뉴얼 → 9~11월 개선 이력 → 12월 입력 방식 개선 → 2월 2차 리뉴얼(예정) 구조를 합성 프로젝트로 재현. 실제 날짜/성과/배포 여부는 증빙 확인 전 미확정. 입력 방식 개선, AI 품질, 추천 위젯의 서로 다른 KPI가 동일 월에 공존하도록 테스트.

## 9. v1.1 확정 범위 — P0 필수, 기존 범위에 우선 적용
- 계층: 개인 워크스페이스 > 고객사 그룹 > 프로젝트. 예: 삼성 S+ > Galaxy Coach / Survey AI. 고객사 없는 독립 프로젝트도 허용. 전체/고객사/프로젝트 전환 및 프로젝트별 지표 사전. 서로 다른 서비스의 완료율 등은 자동 합산 금지; 통합 보고는 프로젝트별 성과와 업무 건수 중심.
- 통합 요구사항 수집함에서 복수 프로젝트 후보를 추천하고 승인 시 프로젝트별 과제로 연결. 원문은 워크스페이스 소유, 과제는 단일 프로젝트 소유. 미분류 원문도 보존.
- 월별 운영 사이클: 요구사항 수집 리포트 → 월별 측정 계획 → 배포 및 데이터 수집 → 결과 리포트. 수집월/기획월/목표월/실제 배포월/성과 관측월 필터 독립 지원. 달력 월과 배포 상대 기간을 분리.
- 배포는 날짜뿐 아니라 환경, 버전, 실제 적용 시각, AS-IS/TO-BE, 국가/법인/OS/사용자군, 복수 과제, 증빙을 기록. 롤백·재배포·부분 배포 이력 보존. 지표 차트에서 배포/외부 이벤트를 선택해 변경 상세 및 관련 결과로 이동.
- 운영 실제 노출일 기준 측정 일정 자동 생성: 기본 D+1/7/14/30, D+90 선택; 기준 기간 기본 직전 28일. 예정일은 준비 일정에만 사용. 지연·결측·비교 불가 표시. 여러 동시 배포의 개별 인과 효과를 단정하지 않음.
- 월별 리포트 마감: 작성 중/데이터 수집 중/검토 중/확정/수정본. 확정 스냅샷은 불변; 늦은 데이터는 최신 보기와 새 수정본에만 반영. 수집·계획·배포·관측 역할별 과제 표시, 이전 달 후속 성과 포함.
- P0 리포트: 요구사항 목록/측정 계획/진행 현황/기능별 결과/월간 결과/선택 기간·개편 전후 요약, 프로젝트/고객사/전체 필터, Markdown 추출. PDF 및 포트폴리오 편집기는 후속.
- 파일럿은 합성 Coach 및 Survey 프로젝트로 검증: Coach는 완료율/재사용률/STT, Survey는 분석 성공률/QA/정합성/소요시간. 실제 고객 데이터·수치는 포함하지 않음.


## v1.2 확장 계약 (2026-11-25)

v1.2는 [확장 명세](06-v1.2-spec.md)와 [추적표](07-requirements-trace.md)에 따라 계정/프로젝트별 연동, GA4 직접 집계, AI 품질·교육·사업 성과·개인 KPI를 추가한다. 기존 P0 및 인과 미확정 원칙은 유지한다. 현재 합성 환경 기반만 구현 중이며 외부 연결/실제 성과 데이터는 없다.

# Phase별 개발 작업지시서
각 Phase는 독립 PR. 선행 Phase 테스트 통과 후 진행. 우선순위 P0=필수, P1=후속. 실제 구현 여부는 테스트 결과로 판단.

## Phase 0 — 기반 및 기존 프로토타입 인수 (P0)
목표: 재현 가능한 개발 환경.
작업: 저장소 조사, ADR 스택 선택, lint/typecheck/test/build 스크립트, env 예시, CI, 합성 seed, 기존 HTML 보존. 기존 HTML은 단일 localStorage 배열/프로젝트 이름 문자열/단일 KPI/비율 수동 계산/텍스트 리포트/JSON export를 지원한다. 실제 AI·서버·CSV·복원·다중 KPI는 없다. 추천 버튼이 기존 KPI 값을 덮어쓸 수 있고 월 포함 여부는 문자열 검색에 의존한다. 운영 코드로 그대로 확장하지 말고 참고로 사용.
완료: fresh clone에서 문서 명령으로 앱 실행, CI 녹색, 실제 비밀키 없음. 기존 저장소 없으면 신규 코드 기반 생성.

## Phase 1 — 프로젝트와 요구사항 기록 (P0, F01~04, F17~18 일부)
작업: 인증/프로젝트 격리, 원문 수집함, 과제 CRUD, 다대다 연결, 상태, 의사결정/기여도, 검색·필터, 보관, v0.1 JSON import preview 및 ID 매핑. 로컬 합성 모드와 실제 인증 모드를 구분. 모바일/데스크톱 shell.
완료: 2개 프로젝트 데이터 격리; 이름 변경 무손실; 원문 하나를 2개 과제에 연결; 새로고침 후 보존; legacy import 재실행 중복 없음.

## Phase 2 — 측정 계획 및 지표 사전 (P0, F05~09)
작업: 월별 전략, 지표 정의/버전, 기존 지표 추천, 복수 KPI, 가설/대상/가드레일, 로그 수집 요건과 기준값 체크. AI schema/provider abstraction 및 규칙 fallback; 원문 분리 추천; 승인·재승인 UX; 추출 요청서 Markdown. 승인 전 비교 기준과 목표를 명확히 편집.
완료: 동일 월 서로 다른 3개 과제에 각각 다른 KPI; 완료율 지표 재사용; 기존 승인 계획 불변; AI 잘못된 JSON/timeout 처리; 로그 존재 여부 unknown 표시; 측정 준비 누락 표시.

## Phase 3 — 배포와 데이터 수집 (P0, F10~13)
작업: 계획/실제 배포/부분배포/롤백, 외부 이벤트, 기간 창 계산, 수동 집계값/CSV preview mapping, 오류 및 중복 검증, import transaction/rollback, 관측 버전 관리, 소스 연결. 비율/개수/합계/평균 산식 엔진. 월별 순사용자 집계는 정확히 산출된 집계값 입력; 사용자 단위 자동 계산은 P1.
완료: 배포월과 수집월 다른 과제 처리; 미확보/0/무효 구분; CSV 잘못된 행 거부; 같은 파일 재업로드 중복 방지; rollback 복구; 실제 운영 미접속.

## Phase 4 — 성과 분석 (P0, F14~15)
작업: 과제별 기준 대비 D7/14/30 결과, 대상/기간/지표 버전 일치 여부, 외부 이벤트 표시, 추세 차트, 절대 변화 및 상대 변화 분리, 공통 KPI 대시보드, 월별 테마 중심 요약. 가설 판정은 사용자 승인; 인과 단정 금지.
완료: 동일 산식/데이터 동일 결과, 비율 40→60은 +20%p/+50%; 0 기준 상대 변화 N/A; 기간/대상 불일치 경고; 부분 배포별 관측 가능; D30 미성숙 코호트 경고.

## Phase 5 — 결과 리포트 및 MVP 출시 준비 (P0, F15~18)
작업: 월별/과제별 Markdown 보고서, 관측 근거/기간/표본/외부 변수/가설 상태/기여도/후속 과제, 스냅샷 및 버전, 백업·복원, 접근성 및 E2E, 배포/운영 가이드. 월별 고정 지표와 집중 지표 분리, 이전 과제의 후속 관측 포함.
완료: 11월 수집→12월 배포→1월 관측이 해당 월별 역할에 각각 표시; 보고서 확정 후 데이터 변경에도 원본 유지; 백업 복원 검증; 모바일 Safari 검증 여부 별도 표기. 배포는 승인 후.

## Phase 6 — 분석 확장 (P1)
작업: Excel, 사용자 단위 익명화 코호트(신규/기존/휴면/복귀), D7/D30 계산, 이벤트 퍼널, 주차별 장기 추이, 분모 자격 및 관측 성숙도, PDF/공유 가능한 익명화 요약, 관측 예정 알림. 사용자 수준 데이터 처리는 조직 승인과 최소 수집 조건 충족 후.
완료: 테스트 코호트 fixture 정답과 일치; 일별 순사용자 중복 제거; 알림 중복 없음; 익명화 출력 검증.

## Phase 7 — 자동화 및 포트폴리오 (P2)
작업: 승인된 Gmail/Slack/P4 등 수집 adapter, GA/DB read-only 집계 adapter, sync cursor/dedup/retry/audit, 팀 권한, 개인 기여도 증빙 및 포트폴리오 export. 서비스별 연결 승인 및 권한 범위 검증. 실제 커넥터 없으면 mock만 완료 표시.
완료: 동기화 중복 방지, 권한 철회 후 수집 중단, 원문 추적, 고객사 비공개 내용 제거 확인, 실제 성과 근거 없는 문구 생성 금지.

## 에이전트 분업
Phase 0~1은 한 에이전트가 기반/스키마 확정. 이후 Claude: 요구사항 UX·AI 계약·리포트 문구; Codex: 계산 엔진·CSV·테스트·권한/CI. 동일 파일/마이그레이션 동시 수정 금지. 인터페이스 확정 후 별도 브랜치, 통합 PR 한 명 지정. 병렬보다 계약 안정화 우선.

### 에이전트 실행 규칙
Phase마다 시작 전 FRD ID 및 테스트 ID 확인 → 구현 계획 및 변경 파일 범위 선언 → 구현 → lint/typecheck/unit/integration/E2E 중 해당 검증 → 인수표 체크 → PR 및 결과 보고. 실패 항목은 완료 처리 금지. 병렬 작업은 Phase 0 계약 확정 후 서로 다른 파일/모듈로 제한. Claude는 UI/AI 흐름, Codex는 계산/DB/테스트 담당을 권장하되 실제 저장소 상태에 맞춰 조정. 운영 배포나 실제 데이터 연결은 별도 승인.


## v1.2 확장 계약 (2026-11-25)

기존 0~7 순서와 완료 조건을 유지한다. 추가 F29~F44의 배치는 [추적표](07-requirements-trace.md)를 따른다. Phase 0은 실행 환경·합성 데이터·계약·추적표만 제공한다. Phase 3의 GA는 mock, 실제 인증·GA/Teams 수집은 승인 후 Phase 7이다. 상태와 다음 착수 조건은 [진행 현황](PROGRESS.md)에 기록한다.

# 요구사항 수집 (붙여넣기 · Gmail · 캘린더)

기준: 2026-11-26 · 화면: **통합 수집함 → 요구사항 수집**

메일, 메신저, 회의록 내용에서 **규칙 기반(`req-rules-1`)**으로 요구사항 후보를 찾는다. 사용자가 확인한 것만 원문으로 등록하고, 원하면 과제 초안도 만든다. AI는 쓰지 않는다.

- 원문은 그대로 보존한다(`rawText`).
- 후보는 근거 문장, 매칭된 규칙 단어, 기한 표현과 함께 보여 준다.
- 저장 전에는 아무것도 기록하지 않는다. 여러 건을 등록해도 한 번에 저장된다(revision +1).
- 같은 링크나 같은 본문은 "이미 수집함에 있음"으로 표시하고, 다시 등록하지 않는다.
- 원문 안의 지시문은 실행하지 않고 읽기만 한다.

## 1. 붙여넣기 (카카오톡·Teams·Slack·회의록·메일)

1. 통합 수집함 → 요구사항 수집 → **붙여넣기**를 고른다.
2. "어디서 온 내용인가요"를 고르고 내용을 붙여넣은 뒤 **요구사항 후보 찾기**를 누른다.
3. 후보를 확인한다. 과제로 만들 후보가 있으면 **선택한 후보로 과제 초안도 만들기**를 켜고 프로젝트를 고른다.
4. **수집함에 등록**을 누른다.

후보는 다음 단위로 나눈다.

- 글머리표(`-`, `1.`, `①` 등)가 있으면 줄 단위
- 대화 로그(`[오후 2:10] 이름: …`)는 발화 단위
- 그 밖에는 문장 단위

인용 답장(`>`), 전달·원본 메시지 머리글, `--` 아래 서명은 후보에서 제외한다. 원문에는 그대로 남는다.

## 2. Gmail 라벨 · 캘린더 (비공개 파일)

메일 본문은 민감하다. 그래서 GA처럼 링크 공개 시트를 쓰지 않고, **본인만 접근하는 웹앱**에서 파일을 받아 가져온다.

1. GA용 Apps Script 프로젝트에 [`Inbox.gs`](../tools/apps-script/coach-ga-export/Inbox.gs)를 추가한다. 최신 `Code.gs`와 `appsscript.json`으로 바꾼다. Gmail과 캘린더의 읽기 전용 권한이 추가되므로, 처음 실행할 때 다시 승인한다.
2. Gmail에서 요구사항 메일에 **`PMZIP` 라벨**을 붙인다. 필터로 자동으로 붙여도 된다.
3. 스크립트 속성은 선택 사항이다.
   - `INBOX_GMAIL_LABEL`: 기본 `PMZIP`
   - `INBOX_DAYS`: 기본 30일
   - `INBOX_CALENDAR_DAYS`: 기본 14일, `0`이면 끔
4. **배포 → 새 배포 → 웹앱**: 실행 계정은 **나**, 액세스 권한은 **나만**으로 한다. "모든 사용자"로 바꾸지 않는다.
5. 웹앱 주소 끝에 `?inbox=1`을 붙여 연다. `pmzip-inbox-export.json`이 내려받아진다. 이 주소를 북마크해 두면 편하다.
6. PM.zip 통합 수집함 → 요구사항 수집 → **Gmail·캘린더 파일**에서 그 파일을 올린다. 후보가 없는 메일은 기본으로 선택되지 않는다.

파일에 담기는 것과 담기지 않는 것은 다음과 같다.

- 보낸 사람은 **도메인만**(`@example.com`) 남기고, 이름과 주소는 넣지 않는다.
- 캘린더는 설명이나 안건이 있는 일정만 가져온다.
- Gmail과 캘린더는 읽기만 하고 아무것도 바꾸지 않는다.
- 회사 메일 내용을 넣기 전에 회사 정책을 확인한다. 가져온 원문은 이 브라우저에만 저장된다.

## 2-1. Gmail · 캘린더를 공유 시트로 받기 (선택, 사용자 결정 2026-11-26)

팀 대부분이 참조(CC)로 받는 메일이라는 사용자 판단에 따라, 파일을 내려받지 않고 시트로 받는 경로도 둔다. 기본값은 꺼짐이다.

1. 스크립트 속성에 **`INBOX_SHEET` = `on`**을 넣는다.
2. **요구사항 메일이 있는 Gmail 계정으로 로그인한 상태에서** `exportInboxToSheet`를 실행해 `pmzip_inbox` 탭이 생기는지 확인한다. 이 계정은 GA 계정과 달라도 된다. 그다음 `installInboxTrigger`를 실행하면 그 계정으로 매일 07시대에 갱신된다. `dailyExport`(GA·DART·StatCounter)와는 별개다.
3. `doGet`은 편집기에서 실행하지 않는다. 웹앱 주소로 여는 함수다. 편집기에서 실행하면 GA 내보내기로 동작한다.
4. PM.zip 통합 수집함 → 요구사항 수집 → **Gmail·캘린더 (시트)** → **시트에서 새 메일 확인**을 누른다. GA 시트 연결을 그대로 쓴다.

> **주의**: 링크 공유 시트는 **링크를 아는 누구나**(팀 밖 포함) 읽을 수 있다. 그래서 시트에 쓰기 전에 다음을 처리한다.
>
> - 인용 답장, 전달 머리글, 서명을 잘라낸다.
> - 본문의 **이메일 주소와 전화번호를 가린다**.
> - 보낸 사람은 도메인만 남긴다.
>
> 고객사 기밀이 본문에 있을 수 있으므로 시트 링크는 팀 안에서만 쓴다. 필요 없어지면 `INBOX_SHEET`를 지우고 `pmzip_inbox` 탭을 삭제한다.

## 3. Slack · Teams 자동 수집

워크스페이스·M365 관리자 승인이 필요해서 아직 자동 수집은 없다. 그동안에는 대화 내용을 복사해 1의 붙여넣기로 수집한다.

## 검증

- 단위: 추출 규칙(메일, 대화 로그, 영어, 신호 없음, 기한)과 `Inbox.gs` 실제 코드를 가짜 Gmail·Calendar로 실행해 계약을 확인했다. 도메인만 남는지, 메모 없는 일정은 빠지는지도 확인했다.
- e2e: 붙여넣기 → 후보 → 원문과 과제 초안 등록(원문 보존, 단일 저장) → 중복 차단을 확인했다. 파일 가져오기 → 후보 없는 메일 제외 → 링크 보존 → 같은 파일 재선택 시 중복 표시도 확인했다.
- 공유 시트 경로: `Inbox.gs` 실제 코드로 인용·서명이 제거되고 이메일·전화번호가 가려지는지 단위 테스트로 확인했다. e2e에서 시트 읽기 → 등록 → 다시 읽을 때 중복 표시까지 확인했다.
- 미검증: 실제 Gmail·Calendar 권한(`gmail.readonly`, `calendar.readonly`)으로 Apps Script를 실행하는 것, 실제 메일·회의록에서 규칙 품질이 어떤지.

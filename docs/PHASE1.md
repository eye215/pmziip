# Phase 1 — 프로젝트와 요구사항 기록

기준: 2026-11-25 · 브랜치 feat/p1-projects-inbox · Phase 0 PR #1 위에 쌓는 별도 PR. main 병합·배포 없음.

## 구현 범위

- F01/F19: 고객사·프로젝트 생성/수정, 설명·시간대·고객사 이동, 보관·복원. 이름과 관계의 식별자는 UUID. 보관 시 과제·원문·연결을 삭제하지 않음.
- F02/F20: 워크스페이스 원문 1건과 복수 프로젝트 과제 연결. 미분류/검토/연결/보관 상태, 출처·요청자 역할·민감도·수집 시각. 원문 수정 전 값·출처를 revision에 보존. 링크는 자동 접근하지 않음.
- F03/F04: 원문에서 복수 과제 수동 작성, 여러 원문을 기존 과제에 연결, 업무 상태·유형·우선순위·담당·문제·대상·기대 변화·기여·근거·대안. 같은 제목 경고는 확인 후 저장. 병합은 사유·승인 후 같은 프로젝트에서만 수행, 원본 보관 및 연결/이력 보존. AI 분류·분리는 미구현이며 수동 승인만 제공.
- F21 일부: 수집/기획/목표월과 월 범위, 날짜 미정·검색·상태·프로젝트 필터. URL로 조회 조건 복원. distinct 과제 ID를 사용. 배포/관측월은 Phase 3~4 미구현으로 제공하지 않음.
- F17 일부: v0.1 배열 JSON 검증/미리보기 → 명시적 프로젝트 매핑·승인 → 단일 저장. 원래 모든 필드와 이전 ID→새 ID 보존. 같은 ID의 달라진 내용은 거절. 같은 자료를 다시 가져오면 중복 제외. 기존 가설/KPI/관측값은 원본으로만 보존하며 후속 기능에 임의 확정하지 않음.
- F18/F44 일부: 합성 세션 소유권/관계 검증, 로컬 키 owner/workspace 분리, 모바일 하단 탐색·데스크톱 사이드 탐색, 로딩/빈/오류·키보드 라벨/편집 제목 포커스. 실제 인증/서버 API/DB 격리를 구현한 것은 아님.

## 데이터 안전 계약

읽기: schemaVersion과 모든 알려진 필드를 검증한다. 알 수 없는 버전/필드·손상·다른 소유자이면 실패 상태로 남기며 합성 seed로 자동 덮어쓰지 않는다. 로컬 원본 백업·다시 읽기 제공.

쓰기: Web Locks의 같은 origin/소유자/워크스페이스 키로 배타 잠금 → 저장된 원본 token과 버전 비교 → 전체 검증 → localStorage 한 키의 setItem → 성공한 뒤 화면 갱신. 지원 안 되는 환경에서는 안전하지 않은 쓰기를 하지 않는다. 잠금 근거: [Web Locks API](https://www.w3.org/TR/web-locks/). quota·다른 탭 변경·검증 실패 시 입력값과 확정 기록을 유지한다. 모든 앱 탭이 동일한 저장 프로토콜을 사용하는 합성 로컬 환경의 보장이다. 브라우저 외부에서 저장소를 지우거나 바꾸는 행위를 복구하는 서버 백업은 아니다.

모든 명령은 복제본에서 수행하고 마지막에 한 번만 저장한다. 원문 연결 해제도 원문 자체를 지우지 않는다. 수정/병합/가져오기 감사 이력 보존. 신규 백업 JSON은 내보내기만 지원하며 전체 복원은 Phase 5 인수 대상이다. 첨부 원본 Apps Script와 운영 localStorage 키를 읽거나 바꾸지 않는다.

날짜 입력은 기기 시간대의 일반 날짜·시간 필드, 저장은 명시적 offset의 ISO instant. 기존 시각 표시를 바꾸지 않은 편집은 원래 초/offset을 보존한다. 존재하지 않는 날짜/시간은 자동 보정하지 않고 거부한다. 월 필터는 프로젝트 시간대를 사용하며, 통합 원문 목록 수집월은 현재 워크스페이스 기준 Asia/Seoul이다. DST 중복 시각의 세부 선택 및 실제 배포 노출 창은 후속 Phase에서 별도 검증한다.

## 검증

- 실패 재현: 구현 전 records 모델을 불러오는 테스트 실패 확인. 폼의 선택 옵션·원문 내용이 라벨에 섞이는 브라우저 실패를 재현 후 명시적 label 연결로 수정.
- unit: 25개(기존 11 + Phase 1 14) 통과. T18/T19/T20의 합성 시나리오, 원문 revision, 동작 전 검증, 충돌/저장 실패, 레거시 보존·중복·내용 충돌·키 순서 독립성.
- lint/typecheck/build: 통과.
- Playwright: 로컬 24개 통과. 기본 화면 회귀 및 7개 기록 시나리오 × Chromium desktop/WebKit 375×812/320×640 = 24개. 두 탭 동시 저장 시 실제 Web Lock 대기·단 한 건 확정, 거절된 탭 입력 보존 포함.
- CI: PR에서 확인. 실제 iPhone Safari/PWA: 미검증.

## 미완료 및 다음 조건

실제 로그인, 사용자 검증 API, DB/RLS 및 T27 운영 인증 인수는 **미구현**이다. 이 PR의 합성 owner 검사를 인증으로 재사용하면 안 된다. 실제 인증/DB 연결은 아직 승인·프로젝트 설정이 없으므로 실행하지 않았다. 제품 Phase 1 전체를 운영 인수 완료로 표시하지 않는다. AI 자동 분류/분리, 신규 백업 전체 복원, 배포/관측월 조회도 후속 대상이다.

Phase 2 로컬 측정 계획 개발은 이 PR의 검사 통과와 저장/소유/원문 계약을 기반으로 한다. 실제 외부 데이터 또는 운영 사용 전에는 실제 인증·DB 테스트와 별도 연결 승인까지 필요하다.

## 상세 화면
- 대시보드: 프로젝트·월 선택, 고정 KPI, 이번 달 목표, 측정 준비 부족 과제, 관측 예정/기한 경과, 최신 배포. 빈 상태에서 첫 과제 등록 CTA.
- 요구사항: 수집함 목록(미분류/검토/연결 완료), 원문 패널, 연결된 과제, 분리 및 병합 확인. 과제 상세 탭: 개요/측정/배포/결과/기록.
- 측정 계획: 가설, KPI 카드(유형, 목표 방향, 산식, 대상, 기간, 기준값, 신규 로그), 추천 근거, 가드레일, 승인 버튼. 승인 시 버전 잠금.
- 데이터: 데이터셋 목록, 스키마 매핑, 오류 검토, 소스 및 관측값 링크. P0 집계 CSV 지원; 사용자 단위 원천 CSV/코호트 엔진은 P1.
- 타임라인: 월 단위 달력/리스트; 수집·계획·배포·롤백·캠페인·성과 관측 구분. 배포 계획과 실제를 구분.
- 리포트: 월별/과제별 탭, 분석 결과·근거·한계·다음 행동·기여도, 초안/확정, Markdown 다운로드.

## 상태 머신
원문: inbox → reviewed → linked → archived.
과제: draft → approved → planned → in_progress → released → archived; canceled 별도. 부분 배포/롤백은 release event 상태로 관리.
측정 계획: draft → approved → superseded. 준비 상태: not_ready / partial / ready / waived. 결과: awaiting_data / observing / inconclusive / supported / not_supported. 마지막 두 값은 사용자 승인에 의해 결정; 전후 상승만으로 자동 확정 금지.

## 산식/관측 기준
완료율 = 유효 완료 세션 / 시작 세션. 시작/완료의 상태 및 세션 중복 제거 규칙 명시. D7 재사용 예시 = 기준 세션 이후 1~7일 내 다시 유효 학습한 사용자 / 7일 관측 가능 기준 사용자. 신규 기준인지 전체 시작 기준인지 별도 지표로 명명. D30 동일. 휴면 복귀는 사전 정의된 휴면 기간 및 대상 분모 필요. 주간/월간 순사용자는 일별 순사용자 합산 금지.
기본 전후 비교: 배포 전 28일과 배포 후 28일, D7/14/30 중간 관측. 부분 배포 대상별 실제 노출일 사용. 달력 월 보고와 배포 상대 기간 분리. 대상·기간·산식 변경 시 비교 불가 또는 경고. 단순 전후 비교는 인과 관계 미확정.

## AI 출력 계약
`requirements[]`: title, source_refs, problem, affected_segment, change, assumptions, open_questions.
`measurement_plan`: hypothesis, metrics[{existing_metric_id|null, name, role, formula_spec, unit, direction, population, exclusions, fields, availability, baseline_window, observation_windows}], confounders, guardrails, evidence_refs, unknowns.
모든 출력은 스키마 검증 및 사람 승인. 없는 로그는 unknown. 목표 수치는 근거가 없으면 null. 기존 승인값 덮어쓰기 금지. 오류/타임아웃 시 규칙 기반 초안 또는 직접 작성 제공.

### 화면별 세부 UX
- 전역 헤더: 고객사/프로젝트 선택, 연월 이동 및 기간 선택. 전체 모드에서도 프로젝트 출처 항상 표시. 필터는 URL 또는 저장된 뷰로 복원.
- 요구사항: 수집일·기획일·목표월 별도 입력, 실제 배포/관측은 연결 기록에서 계산. 조회 기준을 변경하면 동일 과제 ID 유지. 미확정 일자는 별도 필터.
- 배포 상세: 계획/실제/롤백 표시, 환경·대상 범위별 적용 시각, 과제별 변경점, 연관 지표/관측 일정/증빙. 수정은 감사 이력 보존. 타임라인과 차트에서 양방향 이동.
- 결과 리포트: 월별 목표, 요구사항 현황, 고정/집중 KPI, 해당 월 배포, 이전 과제 추적, 외부 이벤트, 데이터 한계, 다음 달 측정 준비, 기여도. 확정 버튼은 누락 경고 및 사용자 확인 후 활성. 수정본은 원본 참조와 사유 필수.
- 상태: report draft → collecting → review → finalized; 수정은 새 draft(version+1), 확정 원본 immutable. 최신 데이터 보기와 확정본 별도 탭.
- 측정 일정: 프로젝트 시간대 기준 실제 적용일 D0. D+N은 적용 이후 N일 관측 완료 예정일이며 D7/D30 리텐션 성숙 조건 별도. 부분 배포/롤백 시 일정 재계산 또는 중단 사유 기록, 이전 일정 보존.
